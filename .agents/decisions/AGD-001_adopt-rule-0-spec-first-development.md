## Context

Source Down 定位为文学化编程工具。
工具将文字、设计说明与代码编织为阅读材料，其自身行为需要可追溯、可验收；
如果转换器、插件和测试各自解释要求，生成的材料也可能遗漏或歪曲输入。

## Decision

[docs/specs/](../../docs/specs/README.md) 是产品要求的唯一规范来源。
本目录拥有语言、架构、工具与开发验收决策；工程说明解释实现；代码、类型、测试和生成材料是投影与证据。

新增或改变行为先写 owning clause，再经公开入口写一个失败测试，完成最小实现并在绿色测试下重构。
原有规范已定义的行为，以修正实现或测试来消除偏差。规范缺口先修订规范。

公开 contract、实现与测试用稳定条款 ID 追踪实际 owner。
审查按条款及其直接依赖选择材料，加入结论必需的真实文件、进程、发布和发行证据。
分别记录实现缺陷、规范缺口、覆盖缺口和过时工程说明。

## Consequences

需求可在语言与实现变化后继续作为符合性标准。ID 与来源可机械核对，语义正确性仍需要实际审查。
声明完成时必须说明已验证的范围，不能把一次成功转换当作整个程序符合全部规范的结论。
