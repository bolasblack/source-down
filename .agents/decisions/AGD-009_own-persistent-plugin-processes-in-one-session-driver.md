## Context

插件的初始化状态可以跨多轮生成复用，文件内容和章节索引需要反映每轮实际读取的材料。
进程启动成本与批次计算成本必须分别测量。持续运行还需要在没有业务请求时观察退出、stdout EOF 和 stderr，
否则停留在上一份完整结果之后的故障只能在下一次调用时被发现。

## Decision

继续使用单 Cargo package 及已有标准库线程、通道、poll 和进程组机制。
一个会话的后台驱动独占全部外部 Child、管道、帧缓冲和协议阶段；其他模块发送命令并观察故障状态。
驱动不向终端写日志，使日志消费者阻塞时也能推进退出、超时和取消。
驱动按初始化、批次、空闲和关闭阶段解释消息；尾部日志缓存有界，避免常驻进程的诊断随时间无限积累。

engine 的 Session 保留有效配置、注册表和外部生命周期，
为每轮新建 SourceStore、批次和输出事实，避免复用进程时带入旧文件内容。PreparedRun 借用 Session，使用 Rust 借用规则表达本轮结果须先发布或丢弃，
再开始下一轮。领域批次不携带子进程句柄。

results 是结果闭合、依赖、来源与 Markdown 校验的共同 owner。Dependency 表达文件系统事实，
SourceSpan 继续表达内容出处。合法缺失路径与二进制材料不通过 UTF-8 文件读取来校验依赖，
因此材料的存在性或目录清单可以参与计算，而不必伪装成内容来源。

一次 render 使用同一会话入口，在准备发布前显式关闭插件，以便退出失败仍能保留旧产物。
Drop 负责异常路径的进程作用域清理。读写、阶段截止时间、关联校验和进程状态在同一驱动中推进，避免两个模块竞争 wait/kill。

## Consequences

新增初始化和关闭阶段，以及持续空闲观察的实现成本；复用的是进程与初始化状态，每轮计算仍处理完整输入和结果。
按帧收集完整批次需要与消息大小相应的内存。一个阻塞式业务调用只等待自己的响应，驱动同时观察其余所有实例。

验收使用真实 PID、逐轮文件修改、缺失依赖、管道容量、后代持管道和发布屏障，
并遵循 [AGD-008](AGD-008_enforce-ninety-percent-test-coverage.md) 的三个覆盖率门槛。
同会话每实例仅一次初始化是确定性证据；耗时改善和峰值内存记录在工程测量中。

实际 watch 命令、监听调度、配置重载、故障恢复与源页面删除规则尚未采纳。
若后续需求需要并发批次、远程传输或大量实例，再依据相应规范和测量重新评估驱动机制。
