## Context

产品规范会随需求调整，决策记录需要保存当时的前提、决定、理由与取舍。
如果决策正文依靠某个可变条款编号才完整，条款后来的变化就会改变读者对历史决定的理解。
项目所有者选择直接禁止这种编号引用，避免维护版本固定链接或规范快照的额外机制。

开发任务还需要区分静态约束检查与实际行为验证，便于单独运行，并防止默认检查遗漏其中一类。

## Decision

AGD 正文自足，禁止引用 SPEC 条款编号，包括正文、链接锚点和代码示例。
产品规范拥有当前行为规则，工程文档说明实现和验收，并维护需要随代码变化的导航。
规则依赖从设计决定经过产品规范和工程说明落实到代码；各层保留自己的权威范围。
代码与测试可以引用所实现的产品条款，工程文档可以链接具体代码作为说明或证据。

`tools/check_docs.py` 在决策文件中检查编号引用，发现违规时给出文件、行号并以失败退出。
这项机械检查不能证明决策内容充分，背景和取舍是否自足仍由审查判断。

`mise run lint` 汇总格式检查、Clippy、文档链接与条款检查，以及 AGD 校验。
`mise run test` 运行 Rust/Python 行为测试并执行独立的覆盖率门槛；检查工具本身的行为测试也保留在这里。
`mise run check` 依赖 lint 和 test，由 mise 复用任务执行。

## Consequences

决策含义不再依赖可变的条款编号。记录决定时需要直接写清必要前提，不能用链接省略理由。
静态检查可以单独执行，完整验收仍需静态检查与行为测试同时通过。
