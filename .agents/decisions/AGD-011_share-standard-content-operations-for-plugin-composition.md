## Context

项目插件需要在解释文字之间插入源码或文档材料。原先每个结果只有一份 Markdown 和来源列表；插件若自行拼接材料，就要复制选择、围栏和来源算法。把返回的文字重新解析为作者指令，又会引入执行次数、名称覆盖和递归的隐含行为。

项目名称注册解决作者调用的归属。插件明确委托发行版材料操作时，需要一个不随项目 override 改变的入口，同时保留现有每轮完整批次及进程所有权。

## Decision

在 directives 模块保留一个标准内容操作目录。include 的材料选择和呈现由同一操作实现拥有；普通内置 Plugin 适配器与内容描述求值器共享该实现。操作返回终值材料、实际来源、依赖或内容错误。普通作者注册仍独立确定最终 owner。

每轮创建操作实例及派生索引，复用该轮 SourceStore；同一响应的重复选择复用结构索引。操作接口不接收伪造的父请求，不重跑整个插件批次。外部会话驱动继续独占进程、管道和取消状态。

通用结果模块先验证完整描述，再按确定顺序求值为带各自来源的 Markdown 块。渲染器只负责块的来源与排版，完成的文字不进入标签提取。旧协议内容在内部成为单块表示；不保留两套渲染流程。

项目 spec 插件继续拥有定义发现与引用统计，用已定位定义的完整物理行范围委托 include。使用确定范围避免再次按锚点查找改变原有定义归属。Python 自用插件直接构造 JSON 内容节点，Rust 自用插件使用公共模型，无需新增语言 SDK。

## Consequences

材料选择与围栏只有一个实现 owner。项目插件无须猜测材料区间；核心也不需要认识项目的编号规则。失败操作产生的依赖与成功来源分开处理，防止输出覆盖材料或删除被依赖的旧报告。

验收观察真实进程返回的描述、最终字节和来源、每轮批次、错误后的产物集合；只比较最终页面不足以证明插件实际使用委托。返回文字重扫和丢弃失败报告须有受控反例验证。

暂未采用插件间任意调用、返回结果再计算参数、跨轮内容缓存或反向 RPC。若未来需要插件根据委托结果作判断，应重新评估交互边界和生命周期，不在文字渲染中隐式加入执行。
