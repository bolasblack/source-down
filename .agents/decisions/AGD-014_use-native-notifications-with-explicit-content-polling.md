## Context

持续生成需要发现编辑器原子保存、目录重建和失败清理期间的修复。
周期读取所有项目正文会让安静项目持续承担摘要成本；仅把正常等待改成通知，
却在每轮建立全项目恢复摘要，同样把未知材料的读取成本留在默认路径。
文件通知可能合并、延迟或丢失，不能证明插件先前读取的内容。

## Decision

固定使用 notify 8.2.0 的 RecommendedWatcher 封装原生后端。
platform 管理通知线程、句柄及显式目录登记；watch 管理观察集合、事实基线、
候选发布资格和修复调度。进程生命周期仍由既有插件驱动拥有。
观察资源跨 Session 关闭及替换保留，Native 和 Poll 共用一个业务协调者。

原生回调只把路径、内容/元数据/结构变化、覆盖失效和故障合并到有界集合并唤醒协调者。
集合最多保留 4096 个不同路径，超过时折叠为覆盖失效；协调者原子收取新批次。
回调不读取材料、计算摘要、修改订阅或等待业务线程。
文件读取和目录成员具有不同含义，普通成员的正文和权限变化不能冒充目录成员变化。
合并保留最严重的通知故障，后到的路径消失不能抹掉已知后端故障。

以安全目录枚举建立 NonRecursive 订阅，先登记目录再枚举其成员。
保存目录身份，覆盖失效后重新建立登记，补齐新覆盖和基线后才释放旧资源。
普通恢复范围只预先建立目录覆盖；未知材料没有对应轮前事实时先补覆盖，
丢弃候选并执行完整补轮。未知修复提示按其实际事实去重，不能冒充来源或依赖声明。

文件身份、查询链、完整二进制摘要及目录事实继续由共享文件系统采集实现拥有。
Poll 复用该采集实现，不启动 notify::PollWatcher 或第二套扫描器。
显式 Poll 从启动使用内容轮询；实际后端资源或不可恢复 I/O 故障导致整个观察器
转为 Poll，报告具体原因，进程内不自动切回。必要目录登记被权限阻止时，也须报告原因，
只有内容采样仍能取得安全事实才继续；普通路径消失先重建安全覆盖。
平台库省略登记故障原因时，登记适配器核对实际节点，不解析错误文本。
静默不发事件不能用于推断后端故障。

初始内部参数为控制检查 50ms、事件安静期 100ms、最长合并等待 1s；Poll 在
前一次采样完成后等待 1s。这些数值按独立性能证据复核，不构成用户参数或实时保证。

## Consequences

安静原生模式无需正文扫描，但启动和拓扑改变仍有目录枚举与句柄成本。
首次未知外部依赖可能要求重建插件并补轮。网络或共享文件系统可能需要作者主动选择 Poll。
显式及降级 Poll 承担完整内容比较与故障恢复扫描成本。

真实三系统 CLI 场景验证原生行为；受控通知 adapter 补充丢失、缓冲溢出和切换窗口证据。
Linux 文件访问记录验证安静期与未知材料正文读取，不能只以 CPU 或业务批次数推断扫描成本。
若锁定库版本的平台行为、句柄成本或通知保障不再满足需要，以新的原生机制证据复核本决定。
