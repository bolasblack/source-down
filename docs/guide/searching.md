# 搜索与继续阅读

先运行 `mise run review`，为本项目完整的创作输入生成阅读页面和搜索快照。
其他项目可以自行选择范围，例如 `source-down render src docs`。
每次完整生成替换当前搜索范围，输出会列出选中的文件数和排除规则。

查找一个名称，再用结果中的 11 位句柄继续阅读保存的快照片段：

```sh
source-down search SourceStore --path src
source-down read '<搜索返回的句柄>' --context 1
```

查询也接受中文短语。多个词共同决定排序；先看看实际命中了哪些字段，再判断材料是否相关。
`--json` 返回相同内容，便于 agent 按字段处理。结果中的来源说明出处；生成内容的出处不等于逐字引用。

正文与上下文共享固定 12000 个 Unicode 字符的预算；长片段会给出下一次读取所需的
UTF-8 字节 `--offset`，按返回值继续即可。中文或 emoji 的字节数可能超过字符数。
来源、出现位置和输入清单各自显示至多五项，用相应 `--cursor` 续取完整清单。
同一内容多次出现时，先选一个 occurrence，再用 `--occurrence` 和 `--context` 阅读那一处的邻近片段。

默认查询会核对当前材料和产物。过期时重新执行覆盖所需范围的 `render`。
需要查看已保存的文字时可以加 `--snapshot`；这时出处属于保存的快照，工具不会提供已核对的当前链接。

已知文件与名称时，可以直接读取当前实体或完整章节：

```sh
source-down read src/cache.py --id 'Cache.get'
source-down read docs/retry.md --id '["重试.策略",0,"下一步"]' --json
```

`--id` 明确将目标解释为文件路径；不传它时，目标始终是搜索句柄。
文件路径相对 `--root`（默认当前目录），解析后的目标须位于根目录内。
此入口直接使用 include 的结构路径规则，保留声明前缀、内部注释、CRLF 和章节原文。
字符串点号分隔父子节点；数组可以表示含点号或数字的名称，并用从零开始的同名下标消除歧义。
以 `[` 开头的选择器参数必须是合法 JSON 数组。

文件读取无需先生成内容，也不加载配置、索引或项目插件。它接受 `--id`、`--root`、
`--offset` 和 `--json`；快照、上下文、occurrence、cursor、配置和输出目录选项不适用。
人类输出以 `Current file` 标识当前文件，JSON 包含 `mode="file"`、完整文件 SHA-256、
选区来源和正文。来源字节范围相对完整文件，正文 offset 相对完整选区。
长选区会给出可直接执行的续读命令，保留路径、选择器和根目录的 shell 引用。

每次文件调用都会重新读取和选择当前版本。拼接多次正文前，比较 `file_sha256` 和 `source`；
任一变化就从头读取。同名下标也按当前文件顺序解释，文件续读不保存历史版本。
搜索句柄需要按原大小写使用。重建后应重新搜索；碰撞检查覆盖当前快照，
完整的历史身份仍由 snapshot 和 record 字段表达。
