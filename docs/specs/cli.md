# CLI、项目配置与输出

<a id="spec-cli-001"></a>
## SPEC-CLI-001 命令入口

公开命令为：

```text
source-down render <path>... [--root DIR] [--config FILE] [--output-dir DIR]
source-down watch <path>... [--root DIR] [--config FILE] [--output-dir DIR] [--poll]
source-down search QUERY [--path PATH] [--limit N] [--json] [--snapshot]
source-down read HANDLE [--context N] [--occurrence ID] [--offset N] [--cursor CURSOR] [--json] [--snapshot]
source-down read FILE --id SELECTOR [--root DIR] [--offset N] [--json]
source-down --help
source-down --version
```

`render` 至少接收一个文件或目录，每个所选源码或 Markdown 文件生成独立页面。`--root` 默认当前工作目录；相对 `DIR` 基于调用者当前工作目录解析，随后取得实际目录作为 project root。输入 path、`--config` 和 `--output-dir` 的相对路径都基于该 root；绝对路径必须位于 root 内。

`--config` 省略时读取 root 下的 `source-down.toml`；该默认文件不存在时使用默认配置。显式指定的配置必须存在。`--output-dir` 默认 `.source-down`，指定时统一改变页面和报告的输出根；具体布局由 SPEC-CLI-007 拥有。选项至多出现一次；`--` 结束选项解析，后续参数均为输入路径。

`render` 的 stdout 保持为空；进度、诊断、实际发布的报告路径及成功时的页面数量写入 stderr。help 和 version 的正文写入 stdout。帮助输出包括命令、参数、默认目录布局、支持语言和退出码；版本输出识别当前发行版本。未知命令、选项、缺少参数和非法配置为用法错误；watch 的可恢复配置故障遵循 SPEC-CLI-008。

search/句柄读取同样接受 root、config、output-dir，采用相同默认值与路径规则。
read 的位置参数为 TARGET；提供 --id 时是当前文件路径，否则是快照句柄，不按外形或文件存在性猜测。
文件读取的参数及路径边界由 [SPEC-SRH-007](search.md#spec-srh-007) 拥有；查询和读取结果由[搜索规范](search.md)拥有。
每次成功生成还须发布完整[搜索快照](search.md#spec-srh-002)。

<a id="spec-cli-002"></a>
## SPEC-CLI-002 文件选择

源码后缀由 [SPEC-REN-001](rendering.md#spec-ren-001) 定义，`.md` 叙述输入由 [SPEC-REN-014](rendering.md#spec-ren-014) 定义，遵循相同选择与排除规则。显式文件先解析为规范目标路径，再使用目标文件名的最后后缀选择输入种类；不支持的显式目标文件报错。目录递归发现受支持后缀，其余文件不进入输入集合。

默认排除任意深度的 `.git`、`target`、`node_modules`、`.source-down` 目录。配置的 `inputs.exclude` 为额外的 root-relative 文件或目录路径，按完整路径或目录子树排除，按字面解释。排除项也约束显式输入；显式选择被排除路径时报错。

目录扫描还排除本次输出根下的 `pages/`、`reports/` 和 `search/` 子树及其临时文件；显式选择其中路径时报输入错误。显式符号链接解析后的目标同样必须通过排除规则。

显式输入若为符号链接，解析为 root 内的实际目标；root 外目标报错。递归遍历跳过符号链接条目，从而避免目录循环。排除规则在规范路径上判断。相同规范路径的重复选择合并；不同路径的硬链接仍作为两个命名输入。

输入以实际目标的 root-relative、`/` 分隔 UTF-8 路径显示。最终文件顺序按该路径的 UTF-8 字节升序确定，与参数顺序和操作系统目录遍历顺序无关。不存在或不可读的显式路径、不可读的待遍历目录、最终零个文件、非法输入文本都导致失败。

<a id="spec-cli-003"></a>
## SPEC-CLI-003 配置格式 v1

配置为 [TOML 1.0.0](https://toml.io/en/v1.0.0) 文档。下面是完整结构的示例，值由各项目提供：

```toml
config_version = 1

[inputs]
exclude = ["fixtures/invalid"]

[plugins.project]
command = ["python3", "tools/project_docs.py"]
directives = ["docs.snippet", "metrics.table"]
timeout_ms = 30000

[plugins.project.options]
label = "Example project"
```

| 字段 | 必填 / 默认 | 约束 |
| --- | --- | --- |
| `config_version` | 配置文件存在时必填 | 整数 `1` |
| `inputs` | 空表 | 仅允许 `exclude` |
| `inputs.exclude` | 空数组 | root-relative、规范的非空路径字符串数组；重复项合并 |
| `plugins` | 空表 | 键为插件 ID，每项为下述封闭表 |
| `plugins.<id>.command` | 必填 | 非空字符串数组；首项非空，每项排除 NUL |
| `plugins.<id>.directives` | 空数组 | 无重复的指令名数组；空数组可用于运行级检查和报告 |
| `plugins.<id>.override` | 空数组 | 本实例显式替换的内置指令名；须为 directives 的无重复子集 |
| `plugins.<id>.timeout_ms` | `30000` | `1..9007199254740991` 的整数，单位毫秒 |
| `plugins.<id>.options` | 空表 | 传给插件的项目私有选项 |

插件 ID 匹配 `[a-z][a-z0-9_-]*`；指令名遵循 [SPEC-DIR-002](directives.md#spec-dir-002)，支持点分名称。同一个命令路径可以注册为多个有不同 ID 的实例，每个实例分别接收自己的请求。

路由先登记[内置目录](standard-directives.md)，再验证项目配置。项目注册的名称与内置名称相同时，
只有该插件 `override` 显式列出这个名称才能替换其 owner，否则配置失败并指出冲突及所需 override。
`override` 中不是当前内置名称的项、不是本实例 directives 的项都使配置失败。
两个项目插件注册同一名称也使配置失败。每个最终名称恰好拥有一个有效处理程序。
所有注册冲突在执行插件和发布 Markdown 前处理，即使本次源码没有使用冲突名称。

启用的实例包括所有项目配置条目，以及仍拥有至少一个有效指令名的内置实例。内置实例的名字全部被显式替换后，该实例退出有效注册。项目插件的启用由配置条目本身确定；每个启用实例的调用由[批次规则](plugins.md#spec-plg-003)统一安排。
此路由只决定作者请求归属；[标准内容委托](plugins.md#spec-plg-007) 使用发行版能力目录，
不受 override 影响，也不重新进入项目路由。

例如，项目明确替换内置 `include` 时使用：

```toml
config_version = 1
[plugins.custom]
command = ["python3", "tools/custom.py"]
directives = ["include"]
override = ["include"]
```

`options` 递归接受字符串、布尔值、数值、数组和表，转换成对应 JSON 值；字符串与数值遵循 [SPEC-DIR-003](directives.md#spec-dir-003) 的可交换值域，TOML 日期/时间值被拒绝。核心传递这些值，插件拥有私有字段的验证。其他层级的未知字段、错误类型和版本被拒绝。

`command` 的程序查找、参数解释、工作目录与交换通道由 [SPEC-PLG-004](plugins.md#spec-plg-004) 定义。

<a id="spec-cli-007"></a>
## SPEC-CLI-007 页面与报告的路径

设输出根为 `O`，所选输入文件的规范 root-relative 路径为 `P`：

| 产物 | 最终路径 |
| --- | --- |
| 源文件页面 | `O/pages/P.md`；在完整原文件名之后追加 `.md` |
| 插件报告 | `O/reports/<完整插件 ID>/<报告名>.md` |
| 搜索快照 | `O/search/index.json`，每次完整生成最后发布 |

例如默认输出根下，`src/queue.ml` 对应 `.source-down/pages/src/queue.ml.md`，`src/queue.mli` 对应 `.source-down/pages/src/queue.mli.md`。插件 `spec` 返回名为 `coverage` 的报告时，路径为 `.source-down/reports/spec/coverage.md`。改变输出根同时改变这些产物的根目录，映射的其余部分保持一致。

插件用所选源文件的规范路径标识附录目标，用[合法报告名](plugins.md#spec-plg-011)标识报告；核心按本条计算最终路径。每个源文件路径对应一个页面，每个完整插件 ID 与报告名的组合对应一个报告。不同插件的同名报告处于各自的目录。

`pages/`、`reports/` 与 `search/` 是核心拥有的生成目录。输出根与生成目标须位于 project root 内；从 project root 起逐级检查已有路径组成部分。遇到符号链接、所需目录实际为普通文件、所需文件实际为目录时，拒绝发布。缺少的普通目录可在发布准备阶段创建。硬链接到来源或依赖的目标同样禁止替换。

生成目标不得覆盖所选源码、配置或本次声明并验证的来源材料以及 [SPEC-PLG-013](plugins.md#spec-plg-013) 的 file 依赖（含缺失路径、无 SourceSpan 的材料及其解析目标）。全部目标须在发布前检查文件身份及文件/目录冲突，包括一个页面文件路径成为另一页面父目录的情况。输出根中其他子目录不属于这次发布的主动写入范围。
创建输出父目录同样不能占用声明为 file 依赖的缺失路径；输出文件也不能占用这些依赖的父路径。

<a id="spec-cli-004"></a>
## SPEC-CLI-004 输出发布

发布先取得全部输入和所有启用插件的有效完整响应，验证依赖、来源、目标、响应闭合以及本次将发布的 Markdown。单次 render 随后按 [SPEC-PLG-008](plugins.md#spec-plg-008) 正常关闭全部外部插件，关闭失败时保留全部旧产物。持续会话可在插件仍运行时发布。在目标父目录准备各个临时文件，完整写入并关闭。直到准备完成，已有最终页面与报告保持原值。插件的检查错误与执行故障按 [SPEC-PLG-008](plugins.md#spec-plg-008) 区分。
响应中的标准内容调用须在发布准备前完成求值和验证。主请求内容错误按检查失败处理；
附录或报告内容错误属于执行故障，保留全部旧产物，失败报告不会通过缺席映射而触发旧报告删除。
有任何检查错误时，本轮页面不发布；此时拟发布的报告若包含标准 link 的导航引用，
须以 `page_not_published` 报告内容故障终止，保留全部旧产物。即使旧输出含该页面也不满足本轮目标资格。
报告不含这种导航引用时，仍按下表更新有效报告。

| 完成检查后的情况 | 发布集合与运行结果 |
| --- | --- |
| 全部请求成功，diagnostics 仅为空或含 warning | 更新报告集合，再发布本次所有源文件页面，最后发布搜索索引；全部完成后成功 |
| 有请求错误或 error 诊断，所有响应仍有效 | 更新报告集合，原有源文件页面与索引保持原值；以检查失败退出 |
| 输入、插件执行、协议、来源、排版或目标校验故障 | 在发布准备完成前终止；已有最终页面、报告与索引保持原值 |

每个启用插件的 `reports` 映射定义该插件本次的完整报告集合。核心先按完整插件 ID、报告名的 UTF-8 字节序替换返回的报告，再按相同顺序删除这些启用插件目录中本次未返回的旧报告；空映射使该实例的报告集合为空。旧报告集合由实例目录下符合 `<合法报告名>.md` 命名规则的条目确定，这些条目须为普通文件；对应条目为目录或符号链接时，在发布前报告目标错误并保留它们。其他名称的条目保持原值。删除集合同样接受 SPEC-CLI-007 的来源保护校验。

报告目录专用于生成物；核心对这个集合的更新使条件性报告在问题消失后不会留下旧缺失清单。插件也可以在检查通过时继续返回同名报告，正文记录当前通过结果。未启用插件的目录保持原值。报告明确显示本次输入清单，排版由 [SPEC-REN-013](rendering.md#spec-ren-013) 拥有。

报告集合更新全部成功后，若满足页面发布条件，按源文件路径的 UTF-8 字节序发布本次页面。单次 render 未选择的页面保持原值；watch 的明确旧页删除集合遵循 SPEC-CLI-012。本次覆盖范围以输入清单为准。

持续会话在每次文件操作前检查 I/O owner 已观察到的会话故障及取消；观察到故障时停止后续操作，按下述规则报告已完成路径。已发布轮次不追溯撤销。

每个文件通过同一父目录中的临时文件原子替换；每次旧报告删除是一次独立文件删除。写入、替换或删除失败时停止后续发布并返回失败，诊断列出已经更新或删除的路径及失败路径。多文件发布期间，已完成的替换与删除保留，尚未处理的文件保持原值。报告更新失败发生于任何页面替换之前。

原子可见性的单位是单个文件；本次发布集合的完整更新以本次成功退出且发布期间没有其他写入者为条件。突然断电后的磁盘持久性由宿主文件系统承担。临时产物在正常失败和可处理取消后清理，已创建的普通目录可以保留。

宿主支持原子替换且已有读取句柄允许替换共享时，读者可以继续读取完整旧文件，新打开的读者取得完整新文件；该读取不阻止发布。拒绝替换共享的句柄、权限或其他实际文件系统错误仍按发布失败处理。

核心主动写入范围为本次页面、启用插件的报告集合、搜索索引、所需生成目录及其发布临时文件。来源链接按各个最终文件的位置计算，遵循[源码转换](rendering.md#spec-ren-009)。

每轮成功生成的候选快照与报告、页面一起完成目标预检和临时文件准备；
全部报告和页面成功后，最后原子替换索引。检查错误、执行故障、准备或部分发布失败均保留旧索引。
最后的索引替换失败须明确报告“页面已发布，索引未更新”及已完成路径，整条命令失败。
索引不提升多文件发布原子性；新索引恰好代表本轮输入选择，不补入未选择的旧页面。
其后句柄读取按 [SPEC-SRH-003](search.md#spec-srh-003) 核对当前事实。
search 子树及索引临时文件受同一来源保护；丢弃 PreparedRun 不发布任何新产物。

<a id="spec-cli-005"></a>
## SPEC-CLI-005 诊断、退出与取消

| 退出码 | 含义 |
| --- | --- |
| `0` | 本次要求的产物全部发布成功，search/read（包括零命中）成功，或 help/version 输出成功 |
| `1` | 文件读取、语言边界、插件检查、插件执行、来源、渲染或发布失败；索引缺失、损坏、过期或句柄无效 |
| `2` | 命令用法或配置错误 |
| `130` | 用户通过取消信号中止：Unix 的 SIGINT，或 Windows 控制台的 Ctrl+C / Ctrl+Break |

search/read 成功要求 stdout 的完整结果写入及最终刷新成功；写入或刷新失败退出 `1`。
stdout 等待可写期间收到取消信号也须停止并退出 `130`。

stderr 的错误须标明类别、可操作的原因；涉及原文时包含 root-relative 路径与一基行号，涉及插件时包含完整插件 ID，涉及某条请求时保留该指令位置。插件 warning 和 error 的结构、来源及汇总顺序由 [SPEC-PLG-012](plugins.md#spec-plg-012) 拥有。stderr 的普通日志内容不决定检查严重级别；原始插件日志只标插件与会话，故障另附 batch_id 和当时请求来源。

已完成报告发布时，无论检查是否通过，stderr 都列出各份当前报告的 root-relative 路径；报告写入失败须明确指出该失败，不能宣称报告已发布。成功页面数量只在本次全部发布完成后报告。

插件超时与取消按[插件生命周期](plugins.md#spec-plg-008)终止并回收已启动的工作。发布期间收到取消时，停止后续替换与删除；已完成操作及尚未处理文件遵循 SPEC-CLI-004，并在诊断中列出已经完成的操作。

<a id="spec-cli-006"></a>
## SPEC-CLI-006 批量调用与成本边界

单文件与多文件的 render 均遵循 [SPEC-PLG-003](plugins.md#spec-plg-003) 的同一批次契约，包括请求范围、调用次数和提前终止规则。

`input_files` 按 [SPEC-PLG-005](plugins.md#spec-plg-005) 传递路径清单，所需材料由插件选择读取；页面数量遵循 [SPEC-REN-007](rendering.md#spec-ren-007)。

help/version 与启动前校验失败不创建插件。单次 render 每启用外部实例初始化一次；公开会话接口跨轮复用同一进程，每轮仍发送完整 input_files 与 requests。
search/read 不创建插件。search 与句柄读取的成本分项见 [SPEC-SRH-003](search.md#spec-srh-003)；
当前文件的读取、解析与选区边界见 [SPEC-SRH-007](search.md#spec-srh-007)。

首版以可观察的调用次数与结果完整性约束这项性能性质。实际耗时、峰值内存、源码体积和展开后输出体积，按项目的性能验收决策测量。

## 验收场景

| 条款 | 输入与动作 | 可观察结果 |
| --- | --- | --- |
| SPEC-CLI-001 | 从不同 cwd 用相同 `--root` 和 root-relative 参数调用 | 输入清单、生成路径及来源链接语义一致 |
| SPEC-CLI-001 | 默认目录与显式 `--output-dir review` 各生成一次 | 页面、报告按对应输出根发布；render 的 stdout 均为空 |
| SPEC-CLI-002 | 文件重复、目录与文件重叠、不同参数顺序 | 输入按规范路径去重并排序，每个源文件只有一个对应页面 |
| SPEC-CLI-002 | 显式未知扩展、空目录、root 外链接或输出子树内输入 | 插件启动前失败，已有最终产物保持原值 |
| SPEC-CLI-003 | 未知字段、重复指令 owner、日期 options、其他 config_version | 插件启动前失败 |
| SPEC-CLI-003 | 项目注册 include，但 override 未列出该名称 | 配置错误并说明冲突与 override 要求 |
| SPEC-CLI-003 | 项目显式 override include | 新 owner 接收请求，被完全替换的内置实例退出有效注册 |

<a id="spec-cli-008"></a>
## SPEC-CLI-008 持续生成入口与生命周期

`source-down watch <path>... [--root DIR] [--config FILE] [--output-dir DIR] [--poll]` 使用与 render 相同的路径、配置和输出参数，至少一个 PATH，保留 `--` 及通用 help/version。默认使用原生文件变化通知；`--poll` 从启动强制使用内容轮询，不创建原生观察器。每次尝试执行完整选择、读取、解析、插件批次、验证和发布。健康 Session 可复用；watch 依次拥有不同固定配置的 Session。

取得首轮基线、读取配置和启动插件之前，先建立基本及普通恢复目录的通知覆盖；首轮立即安排，不要求用户先编辑。stdout 始终为空，stderr 显示实际模式 native 或 poll、进程内轮次号、开始、结果、已发布报告和成功页面数；失败区分检查、配置、执行、发布和观察故障，并说明继续监听的范围。同一等待状态不反复输出同一错误；新轮仍可报告相同错误。

argv、无效 root 或 argv 字面查询已越出 root 的静态约束错误退出 2。TOML 错误、显式配置暂缺、输入暂缺/不可读、零输入、root 内查询链接越界/循环、语法、插件及发布错误，只要 root 和恢复范围可安全观察，就保留旧产物并等待修复。不能因运行错误的退出码或文字含“越界”而把它当作静态约束错误。root 不可读、两种观察模式均无法建立安全覆盖或受管进程无法清理时退出 1。

SIGINT 或 Windows Ctrl+C/Ctrl+Break 取消调度和当前工作，停止观察器、终止并回收受管进程、清理发布临时文件，退出 130。stdin EOF 不结束 watch。部分发布遵循 SPEC-CLI-004，已完成操作不撤销。等待仍检查取消及空闲 Session 健康；控制检查不触发正文扫描。


<a id="spec-cli-009"></a>
## SPEC-CLI-009 变化观察与观察范围

原生模式由变化提示启动事实核对；没有提示的健康或故障空闲期，不定时打开文件正文或计算摘要，也不运行隐藏的周期全量扫描。显式或已报告降级的 poll 模式定时完整采样，不重叠扫描。采样在目录条目和固定大小二进制读取块之间检查取消与 Session 健康。需要核对 file 时，SHA-256 比较完整字节，同大小、同 mtime 不免除读取。一次采样按路径及事实种类去重并保留全部 owner。

file 事实包括查询拼写、链接解析链与目标、存在性、类型、原生文件身份及完整摘要。directory 事实包括这些路径/类型事实及成员名称、类型和链接文本；recursive=false 仅含直接成员，true 含后代目录成员，均不跟随成员符号链接，也不把普通成员内容当作声明。缺失路径保留最长可解析父链、剩余尾部和缺失/非目录区别；不可读、根外和循环为有安全父链证据的错误，不能伪装成缺失或空目录。

基本观察包括原输入查询及链接链、按 SPEC-CLI-002 选择规则得到的发现目录和所选内容、配置查询（含不存在的默认配置）与 root 内含路径分隔符的显式插件程序。选择过程只有一个规则 owner，普通排除和不跟随成员链接规则同样适用。程序后的 argv 项不推断为文件。

每轮观察还包括读取前登记的 core 文件/材料查询、SourceStore 实际来源字节和完整有效插件结果的 dependencies；包括失败的 include 查询和有效检查失败返回的依赖。来源与依赖保持各自含义，未回复的插件不被视为空依赖。

普通恢复范围递归覆盖 root 下目录拓扑及普通文件变化提示，跳过任意深度的 `.git`、`target`、`node_modules`、`.source-down` 及实际输出三个生成子树，不跟随成员链接，不采用用户的 inputs.exclude。原生模式在首次尝试前建立并跨 Session 保留这项覆盖，可以枚举目录和成员，不能为未知材料读取全 root 正文；健康时无关普通文件变化只用于维护目录覆盖，不触发业务轮次。poll 模式可在每次尝试前建立恢复全文基线，故障等待额外扫描恢复范围；健康空闲只扫描基本/每轮范围。显式配置、程序、core 查询和已声明依赖可跨越普通排除，生成子树禁令仍优先。普通排除目录内尚未被查询/声明的材料不在首次崩溃自动恢复保证内，诊断说明可通过修改配置/普通项目文件或重启恢复。

原生覆盖包括查询/实际目标的父目录、可变链接所在目录、目录自身及 root 内父目录；缺失路径覆盖最近的安全祖先。新目录先登记覆盖再枚举和采样，删除/重建后重新确认目录身份及有效订阅；不能只凭同路径、同成员认定旧订阅有效。先加新覆盖，取得基线并确认所有 owner 后才移除旧覆盖。根外链接只保留安全根内前缀，不能监听或读取根外树。

事件仅为核对提示，不是内容证据。保留改名两端；过滤只读打开/关闭、读取及纯访问时间事件，保留写入、创建、删除、改名、权限及未知变化。提示收集必须有界，满时标记范围失效；收取原子交换为独立批次，处理期间的新提示留给下一批。

原生模式保证处理已交付提示、报告的通知丢失及订阅登记时重新发现的状态；静默不发事件的文件系统（例如部分网络或共享路径）需主动使用 `--poll`，不能凭沉默自动降级。poll 保证发现采样中存在或持续到下次采样的不同状态。均不保证逐次呈现快速出现又恢复的中间状态，仍保留 SPEC-MOD-004 的非原子读取限制。

原生初始化或必要订阅因后端不支持、资源上限或无法恢复的通知 I/O 故障不能覆盖范围时，显示具体原因并切换整个 watch 为 poll，进程内不自动切回。订阅期间的普通删除先修订安全父链；权限失败不能被降级成功掩盖，内部配置错误不能作为正常后端限制吞掉。切换保留已知事实及 pending，先核对再发布；poll 也无法覆盖时明确等待可恢复错误或退出，不能声称正常监听。

必要目录订阅被权限阻止时，明确报告权限原因；只有 poll 能安全采集同一查询事实时才继续。
不能在文件可读、目录可遍历但无法登记原生观察时声称已覆盖该文件。
无法采集的查询保留其可恢复错误，root 或恢复覆盖本身不可用时按 SPEC-CLI-008 退出。

<a id="spec-cli-010"></a>
## SPEC-CLI-010 串行轮次与修复窗口

watch 串行生成与发布。订阅先于基线；原生提示合并后核对基本/已知范围，事实不变不调用插件。开始完整 prepare 前取得有覆盖的轮前事实并收取此前提示，运行期间的提示留在新批次。prepare 后补齐本轮查询/依赖的订阅并采样，比较轮前及实际读取事实；相关事实变化、相关写入提示或覆盖失效使尚未发布的候选丢弃。订阅成功、队列为空都不是全局文件系统 barrier。

新增 core 查询或依赖没有同语义轮前事实时，先登记覆盖和当前事实，明确报告候选未发布，再执行完整新轮。已有输入事实只有精确包含相同查询、链接链及类型所需数据才可复用；目录覆盖和事后内容不能补足读取前证据。原生路径不借用 root 恢复全文扫描为未知依赖补证。新增未知外部依赖在补轮前保守重建 Session；内置材料无此重启要求。

完整有效检查失败同样比较依赖，稳定后发布允许的报告并等待变化；页面和索引保持。执行故障终止 Session，保留最后完整依赖与本次安全已知查询的并集，之后完整有效结果才替换动态依赖。相同故障没有文件变化时不计时重试。

观察器及 pending 跨 abort、清理和 Session 重建存活。所有故障等待路径均保留故障前已知事实，与清理完成后的适用集合比较，包括普通排除目录的显式程序/依赖；适用于初始配置错误、批次失败、配置重启关闭失败、空闲退出及发布失败。已知差异触发新轮，不能用清理后基线吞掉修复。

普通恢复域中尚未声明的路径，只有尝试前覆盖所收到、且尚未消费的合格变化提示才参与故障恢复。按提示采集安全路径事实：首次未知可触发一次明确的发现尝试，并保存事实；后续相同事实不重试，去重事实跨失败尝试保留。未知提示不是依赖或来源证据，采集错误保留为错误；不全扫未知正文。开始本轮前已处理的提示不能无限重放。相同内容原地写 marker 后崩溃至多由首次未知提示增加一次尝试，不能无限启动。

普通恢复排除按目录边界应用；同名普通文件仍可提供修复提示。
已知查询的提示通过其已保存事实比较，不能因重复提示被重新归类为首次未知修复。
普通恢复域中的链接提示比较安全解析链与链接文本，不读取链接目标正文，也不把目标子树纳入恢复扫描。

Rescan、无路径提示、后端报告丢失或有界缓冲溢出使范围失效：重查全部基本/已知事实及目录覆盖/身份，健康时无实际变化不重启插件。尚未发布的候选丢弃；已经进入发布的普通 dirty/Rescan 保留到完成后核对，不当作发布错误。故障等待中未知恢复范围的覆盖失效可触发一次明确尝试，不能写成已证实内容变化。

发布后以发布前事实及实际操作核对 pending，输入变化安排下一轮，不撤销已完成操作，也不能先把当前值存成基线再丢弃提示。后端切换先丢弃未发布候选并保留变化；poll 缺失未知恢复基线时保留未知，可因覆盖失效进行一次明确尝试。无差异、未知修复提示或覆盖失效时，不计时重试相同故障。

<a id="spec-cli-011"></a>
## SPEC-CLI-011 配置、程序及插件依赖重载

root、原输入表达式、配置查询和输出位置由启动参数固定。配置的内容、身份、存在性或链接链变化时，丢弃候选并关闭旧 Session，重新加载配置。新配置无效或显式配置缺失时不得使用旧配置发布；省略 --config 时删除默认文件合法地恢复默认值。

root 内含路径分隔符的程序项由 core 观察。外部插件声明影响自身计算的项目脚本、模块和其他材料；其任一依赖变化保守重建整个 Session。仅属于内置操作的材料变化可复用健康外部进程；同时有外部 owner 时依外部规则重启。root 外程序、PATH 查找结果及继承环境不在在线重载保证内，改变后需重启 watch。

任一插件在空闲时退出（含 0）也是会话故障。关闭失败先报告并完成强制清理，确认清理后依 SPEC-CLI-010 的恢复条件建立新 Session；清理无法完成则退出 1。观察器跨 Session 存活，后端切换与插件重启具有不同原因和生命周期。调度层不取得 Child 或自行杀插件，进程和管道由既有 I/O owner 负责。旧会话出错后不再发送业务批次。

<a id="spec-cli-012"></a>
## SPEC-CLI-012 输出排除、页面 ownership 与发布恢复

`O/pages`、`O/reports`、`O/search` 和内部临时文件不作为普通 watch 触发事实。精确依赖、配置或程序的查询/解析目标落入这些子树时报告生成物依赖循环，等待修复；不能静默丢弃声明。目录依赖可指向 root 或输出祖先，其触发投影去掉三个子树及入口，并可去掉 publication 明确创建的父目录变化，其他成员不豁免。搜索仍保存完整声明事实，索引格式版本保持 1。

watch 只删除它拥有的旧页面。启动可接管相同 output_root、config_path 和排序去重后的原输入表达式对应的既有索引；索引必须通过 Reader 共用的闭合格式、身份和句柄碰撞校验，仅跳过来源 freshness。每个页面还须是安全的普通文件，满足来源保护，且内容摘要与索引一致。缺失页面无须接管；被手改的页面保留并提示不接管。索引缺失、损坏或范围不同只产生一次不接管说明，不猜测清理；之后只拥有本进程实际发布的页面。

成功候选删除集合为已拥有页面减本轮选中页面。目录发现的删除、重命名或 exclude 改变可退出集合；显式输入缺失、非法或最终零输入仍失败并保留旧页面/索引。检查失败不删除页面；执行/准备失败不替换或删除。单次 render 不取得额外清空语义，已移除插件的旧报告保持现行规则。

旧页面删除由 publication 与替换一起完成来源/依赖/硬链接/符号链接/类型/取消预检，全部新文件临时写入完成后才发布。顺序为报告替换、旧报告删除、本轮页面排序替换、旧页面排序删除、最后索引替换。缺失旧页删除幂等；部分失败保留已完成操作与旧索引。候选索引的 prospective 目录事实包含明确的新写入、旧报告和旧页面删除及创建的父目录，使自身发布后默认 search/read 即刻可用。

publication 返回结构化的已完成替换/删除、失败目标/父链及失败时已知的阻断事实；watch 据实际操作更新页面 ownership，失败后终止 Session。取得阻断事实后及时为具体路径及安全父链增加覆盖并跨清理保留，即使它在生成树中；只比较相关存在性、类型、链接、权限或冲突内容，清理后与失败时事实比较，避免吞掉订阅/清理期间修复。成功或失败原因变化后替换该观察。未知仍为未知，不解析 stderr 获取路径。

事件过滤先识别阻断 owner，再排除普通生成物；不在 callback 无条件丢弃输出前缀，也不监听整个输出树的业务变化。发布自建父目录的延迟通知按实际操作及事实投影判定，不能忽略一段时间的全部父目录事件。实际后端故障导致覆盖无法继续，或取消时，经发布检查在下个安全操作边界停止并保留进度；普通 dirty/Rescan 留待发布后核对，callback 不直接中断替换或撤销操作。

健康空闲时手改生成文件不触发自动修复，默认 search/read 仍检查输出 freshness。磁盘空间、未反映为路径事实的 ACL 等修复不保证自动触发，诊断提示修改输入/配置或重新运行。多个进程同时写同一输出不具备多写者一致性保证。
