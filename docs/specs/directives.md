# 项目指令语法

本页拥有注释正文与直接输入的 Markdown 正文中的指令语法与解析结果。[插件协议](plugins.md)拥有执行与响应，
[源码转换](rendering.md)拥有语言注释提取、原文位置和 Markdown 排版。

<a id="spec-dir-001"></a>
## SPEC-DIR-001 模板标签与项目语义

一个指令把原文位置、名称、位置参数和命名参数交给注册的插件，取得该位置的 Markdown。
名称和参数的业务含义由插件定义；核心按本页的有限标签语法提取值并交给 owner。

~~~text
{% include "docs/guide.md" id="Overview" %}
{% metrics.table "daily" limit=10 compact=true %}
{% overview %}
~~~

定界符采用常见模板标签的 `{%` 与 `%}` 拼写。本页列出的名称和值构成完整语法，
每个标签独立产生一次请求；文本只按这里定义的值解析，插件取得数据后执行自己的行为。

<a id="spec-dir-002"></a>
## SPEC-DIR-002 单行形式与名称

每个标签须在一条物理行内结束，可以独占整行，也可以嵌入普通正文：

~~~text
{% name positional-value ... key=value ... %}
~~~

`{%` 后、`%}` 前的 ASCII space 或 tab 可省略。名称与参数、相邻参数之间必须有
一个或多个 space 或 tab；命名参数的 `=` 两侧允许 space 或 tab。
标签独占顶层物理行时，前后允许 space/tab，行首最多 3 个 space；构成 indented code 的缩进按代码处理。
标签前后有正文时为内联调用，外侧正文不属于参数；同一物理行可有多个独立标签。
无参数时写 `{% overview %}`，其两组参数均为空。

名称由一个或多个以 `.` 分隔的组件组成，每个组件匹配 `[a-z][a-z0-9_-]*`。
名称大小写敏感；路由按整个名称精确匹配。命名参数 key 恰好是一个这样的组件。
位置参数必须全部位于命名参数之前；命名参数 key 在一条指令中唯一。

字符串中的 `%}` 属于数据。只有字符串外的 `%}` 结束标签；单行末尾仍未结束的
标签或字符串为语法错误。

<a id="spec-dir-003"></a>
## SPEC-DIR-003 值与交换数据域

每个参数值为以下一种标量或 JSON 数组；路径和普通文字使用带引号的字符串。

| 拼写 | 解析结果 |
| --- | --- |
| 双引号字符串 | 按 RFC 8259 JSON 字符串规则解码，包括 Unicode 与控制字符转义 |
| 单引号字符串 | 保留引号内文字；仅 `\\` 和 `\'` 是合法转义，分别得到反斜杠与单引号 |
| `true`、`false`、`null` | 对应 JSON 布尔值或 null，大小写敏感 |
| JSON 数值拼写 | 按下述数值域取得 JSON number |
| JSON 数组 | 按严格 JSON 递归解码；元素可为标量、数组或对象 |

两种字符串解码后必须是 Unicode scalar value 序列。原始 U+0000–U+001F 字符
不能直接出现在字符串内；双引号形式可用 JSON 转义表达控制字符。拒绝孤立 surrogate。
单引号字符串中的其他反斜杠转义为错误；逻辑换行可用双引号形式的 `\n` 表达。

数值拼写遵循 [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)；
整数字面值范围为 `-9007199254740991..9007199254740991`。
包含小数点或指数的数值按 IEEE 754 binary64、round-to-nearest ties-to-even 解释，
结果须有限；若所得值为整数，也必须位于上述安全整数范围。
需要保留精确十进制或其他文字格式时，使用字符串。

协议与配置可以在数组、对象中组合这些 JSON 标量；数组顺序和字符串内容保持，
对象成员名唯一。对象成员顺序、数值拼写和空白不是数据身份。
标签数组必须在同一物理行结束；内部仅使用 JSON 双引号字符串，拒绝尾逗号、重复对象键和非法值域。
数组内字符串中的 `%}`、括号及 Markdown 字符均为数据，不改变标签或块边界。
标签不接受顶层对象字面量。数组的语法与数据域错误在插件启动前报告；插件解释数组的业务含义。
核心验证语法和数据域；插件验证参数数量、字段名称、范围及业务含义。

<a id="spec-dir-004"></a>
## SPEC-DIR-004 Markdown 优先级与字面示例

注释清理后，使用 CommonMark 0.31.2 的块级上下文，并加入 Source Down 指令叶子块。
顶层普通文本行中的 `{%` 是保留的指令起点，可中断普通 paragraph。
指令块在 paragraph 的 inline 解析之前识别；参数内容对 Markdown 解析不透明。
相邻两行指令分别产生请求，无需空行。指令之后重新按块级规则识别剩余正文。

fenced code、indented code、HTML block 和行内 code span 中的标签保持字面；转义的 `\{%` 也不触发。
其余正文（包括标题、列表和引用的正文）允许内联标签，按同一名称与参数规则求值，
不区分标签是否位于 Markdown 链接目标中。合法标签的参数作为整体数据，不改变外层 Markdown 上下文。
setext 标题下划线不能把前一行已识别的指令变为标题内容。

多行 inline code 在指令块切分之后解析；跨行反引号不能越过独立指令块来屏蔽它。
完整标签的字面示例使用 fenced code 或行首 `\{%` 转义；转义行按原拼写保留。

~~~text
{% note "first ` marker" %}
{% note "second ` marker" %}
~~~

上例产生两个请求。外层编程语言始终先决定注释边界，参数必须能合法放入该语言注释；
必要时可用双引号字符串的等价 JSON 转义避开外层注释终止符。

<a id="spec-dir-005"></a>
## SPEC-DIR-005 语法错误与路由错误

在 SPEC-DIR-004 的可识别位置，`{%` 表达指令意图。
缺失或非法名称、未知 token、未闭合引号或标签、重复 key、命名参数后的位置参数，
均使运行失败，不能作为普通正文成功生成。
代码区域与转义按 SPEC-DIR-004 处理，与名称是否注册无关。

合法名称没有注册 owner 时是路由错误。语法和路由错误在启动插件前报告。
诊断包含原文件路径、一基行号及可定位的原字节位置，退出遵循 [CLI](cli.md#spec-cli-005)。

<a id="spec-dir-006"></a>
## SPEC-DIR-006 源位置与解析结果

解析产生完整名称、`arguments` 和原始 SourceSpan。`arguments` 是封闭对象：

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `positional` | JSON 数组 | 按标签中的顺序保存位置参数值（标量或数组）；必填，可为空 |
| `named` | JSON 对象 | key 对应命名参数，值为标量或数组；必填，可为空 |

源位置从起始 `{%` 的 `{` 到结束 `%}` 的 `}` 之后，排除外侧缩进、尾随空白、
注释 marker 和行终止符。注释清理保留从正文到原始源码字节的映射。
整行替换消费完整指令行及存在的 LF；内联替换只消费标签字节，外围文字、空白和换行保持。
两种位置的原始 SourceSpan 都指向准确标签字节，不增加 wire 字段。

前文、后文及相邻指令各自在原位置排版，切分见 [SPEC-REN-011](rendering.md#spec-ren-011)。
插件直接取得结构化参数；返回内容遵循 [SPEC-PLG-007](plugins.md#spec-plg-007) 的单层展开。

## SPEC-DIR-007 验收场景

| 条款 | 注释正文中的输入 | 必须观察到 |
| --- | --- | --- |
| SPEC-DIR-002 | `{% overview %}` | 空 positional 与 named |
| SPEC-DIR-002 | `{%docs.snippet 'A B' section = "Overview"%}` | 名称完整，位置字符串与命名字符串保持 |
| SPEC-DIR-002 | `{% note "%} still text" %}` | %} 保留在字符串内 |
| SPEC-DIR-003 | 引号字符串、null、布尔值与有限小数 | 插件收到对应标量 |
| SPEC-DIR-003 | `id=["章节",0,{"nested":[true,null,"%}"]}]` | 任意外部插件收到真实数组及嵌套数据，非 JSON 文本字符串 |
| SPEC-DIR-003 | 错误转义、孤立 surrogate、超出安全范围整数或 `1e400` | 插件启动前失败 |
| SPEC-DIR-004 | 相邻标签各含一个反引号 | 两个请求，反引号保留为参数数据 |
| SPEC-DIR-004 | fence、indent、HTML、code span 或 `\{% overview %}` | 保留字面内容，零请求 |
| SPEC-DIR-004 | 正文、标题、列表和引用内有标签 | 通用内联求值，外围字节与结构保持 |
| SPEC-DIR-004 | 普通段落、标签、四空格缩进标签连续三行 | 中间标签中断段落，最后一行为代码 |
| SPEC-DIR-004 | 三行分别为反引号、标签、反引号 | 中间标签成为指令块 |
| SPEC-DIR-005 | 重复 key、位置参数在 key 后、缺 `%}` | 明确失败并带原始位置 |
| SPEC-DIR-006 | 标签前有中文、不同注释 marker 与 CRLF | 原字节区间和行号准确 |
