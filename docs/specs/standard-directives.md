# 内置内容插件

本页定义随 Source Down 分发的 `include` 与 `link` 指令的内容语义。
模板定界、参数值域与字面文本由[指令语法](directives.md)拥有；注册、批处理与覆盖
由[插件协议](plugins.md)及 [CLI 配置](cli.md)拥有。这里的指令是可替换的内容 owner。

<a id="spec-blt-001"></a>
## SPEC-BLT-001 注册与批次契约

默认注册两个独立插件：`builtin:include` 拥有 `include`，`builtin:link` 拥有 `link`。
其他名称由项目自行注册。
名称注册、显式替换与启用条件遵循 [SPEC-CLI-003](cli.md#spec-cli-003)。
有效处理程序拥有参数解释和内容语义，通用调用边界见 [SPEC-PLG-001](plugins.md#spec-plg-001)。

每个请求的结果及批次完整性遵循 [SPEC-PLG-006](plugins.md#spec-plg-006)，
运行是否成功及是否发布按 [SPEC-CLI-004](cli.md#spec-cli-004) 判断。
内置插件返回完整批次响应，`dependencies` 遵循 [SPEC-PLG-013](plugins.md#spec-plg-013)，`append`、`reports` 和 `diagnostics` 分别为空数组、空对象和空数组。
空请求批次正常返回空 `results`，处理过程遵循相同的每次运行一次调用规则。
内置插件的材料读取与来源校验使用 [SPEC-MOD-004](model.md#spec-mod-004) 定义的同一版本文件事实。
内置批次适配器验证请求的路由名称，为各请求返回相应的 `standard_call` 内容描述；
核心按 [SPEC-PLG-007](plugins.md#spec-plg-007) 在实际内容位置统一求值。
适配器本身不提前读取材料或执行内容操作，实际依赖由求值器归入该内置实例。

发行版标准内容能力目录第一版提供 `include` 与 `link`，可按 [SPEC-PLG-007](plugins.md#spec-plg-007) 明确委托。
该目录独立于作者指令的最终 owner 表；普通批次与标准委托共享本页的材料操作语义。
项目 override 改变作者请求的 owner，标准委托始终使用发行版操作，并保留其实际来源、依赖和错误。

<a id="spec-blt-002"></a>
## SPEC-BLT-002 公共参数与文件事实

`include` 恰好接受一个位置参数，类型为非空字符串，表示 project root 内文件的相对路径。
路径使用 `/`，须符合 [SourceSpan 路径规则](model.md#spec-mod-003)；绝对路径、`.`、`..`
和空组成部分是参数错误。符号链接解析后的目标也须位于 project root 内。
材料可以使用任意文件后缀，但必须满足模型的 UTF-8、BOM、NUL 与来源位置契约。
成功结果的 `sources` 恰好包含一个区间，指向所选材料的原始字节。
材料路径以符号链接解析后的规范拼写返回；源正文中的相对链接按
[原文保留规则](rendering.md#spec-ren-009)保留。

合法参数形成 root 内材料路径后、尝试读取前登记 file 依赖，保留查询拼写。缺文件、缺章节、空选区及有效请求错误均保留该依赖。非法参数不制造路径；主动拒绝的根外链接或边界无法确定路径保持 source_error，不提交不合法依赖。

位置参数个数、类型、未知 named 参数及已定义参数的错误类型均返回 `invalid_arguments`。
读取失败、根外链接目标或材料文本非法返回 `source_error`。
字节为空或仅包含 ASCII space、tab、CR、LF 的选择返回 `empty_selection`。
这些内容错误归于具体请求，以标准 code 和材料或参数上下文报告；其他有效请求继续求值。

<a id="spec-blt-003"></a>
## SPEC-BLT-003 include 参数、材料类型与呈现

```text
{% include "docs/design.md" id=["Overview",0,"Details"] %}
{% include "src/lib.rs" id="parse" %}
{% include "docs/design.md" lines=[1,12] %}
{% include "notes.txt" id="Overview" %}
```

允许的命名参数为 `id`、`lines`；未知参数报 `invalid_arguments`。
`id` 使用 SPEC-BLT-007 的字符串或数组路径；`lines` 为 SPEC-BLT-005 的字符串或二元素数组。
两种选择器互斥，均省略时选全文。Markdown 标题和各语言代码实体使用相同的结构路径、
直接子节点匹配、同名下标与错误规则；材料解析器提供各自的名称、层级和原始区间。

材料分类根据符号链接解析后的规范路径、区分扩展名大小写：

| 条件 | 解析格式 | 插件生成的 Markdown |
| --- | --- | --- |
| SPEC-REN-001 中六种源码语言的后缀 | 对应语言 | 原始选区的代码块，标签为该语言标签 |
| 其他后缀或无后缀（含 `.md`、README、notes.txt） | Markdown | 原始 Markdown 正文 |

源码结构由[代码实体](entities.md)定义，Markdown 结构由 SPEC-BLT-004 定义。
全文和行范围无需解析实体树；有 `id` 时必须先完成可靠的结构选择。
生成内容的插件负责完整 Markdown：内置 include 按上表生成结果，项目插件可以直接构造
所需的正文或完整代码块，再按插件协议返回内容与实际来源。

正文呈现与选区原始字节相等；代码呈现按 SPEC-BLT-006 包围同一选区。
最终是否满足独立 Markdown block 边界由[渲染规范](rendering.md#spec-ren-011)判断。
返回内容不再次执行其中的指令，遵循[单层展开规则](plugins.md#spec-plg-007)。

<a id="spec-blt-004"></a>
## SPEC-BLT-004 章节匹配与范围

章节索引按照 CommonMark 0.31.2 识别文档顶层的 ATX 和 setext heading。
列表、blockquote、code block 或 HTML block 内的 heading 样式文本不进入索引。
heading 的匹配文本为其行内 Text 与 Code 内容按顺序连接，soft/hard break 变为一个
ASCII space；图片 alt text 参与连接，链接目的地址和行内 HTML 标签不参与。
不额外修剪、折叠空白、改变大小写或产生 slug。

heading 的紧邻上一物理行若独占一个 `<a id="VALUE"></a>`，该行属于 heading 的前置锚点。
此语法允许整行前后有 ASCII space 或 tab；标签、属性名、双引号和其他字节须按示例拼写。
VALUE 非空，不能含 `"`、`<`、`>`、ASCII 控制字符或 `&`；按原字节匹配。
锚点行和 heading 间恰好一个 LF 或 CRLF，二者之间没有空行或其他内容。
只有实际位于顶层普通正文中的该锚点行参与匹配；代码和容器内的同样文本不参与。

文件有虚拟根，每个 heading 的父节点是前方仍开放且级别更低的最近 heading，没有则归根。
跳级不补节点；文档总标题与空标题均保留真实层级。`id` 按完整标题文本逐层精确匹配，
使用 SPEC-BLT-007；数组中的空字符串可以选择真实空标题。
标题的名称取其完整匹配文本；前置锚点属于章节原文，不提供额外的结构名称。

选择从匹配 heading 所在行开始；有前置锚点时，从该锚点所在行开始。
范围包含该 heading 及后续正文和更低级 heading，直到下一个同级或更高级顶层 heading
的开始行之前；该终点 heading 有前置锚点时，终点提前到它的锚点行之前。
文件结束前没有这样的 heading 时选择到 EOF。
空行、CRLF 与所有选区字节保持，不在边缘 trim。

<a id="spec-blt-005"></a>
## SPEC-BLT-005 include 行选择

```text
{% include "src/lib.rs" %}
{% include "src/lib.rs" lines="3-8" %}
{% include "src/lib.rs" lines=[3,8] %}
{% include "examples/request.txt" lines="1-1" %}
```

省略 `lines` 时选择全文；提供时接受字符串 `"N-M"` 或固定二元素数组 `[N,M]`，
表示一基、包含两端的连续行范围，满足 `1 ≤ N ≤ M ≤ 文件行数`。
字符串端点是不带前导零的正十进制整数。数组端点是交换数据域内的正整数，
按数值判断，`1`、`1.0`、`1e0` 等价，不截断或四舍五入。
非字符串且非数组、数组长度不等于二、数组元素不是 JSON number 返回 `invalid_arguments`；
布尔值、数字字符串、null、对象和嵌套数组均不是数字端点。
合法 JSON 数值中的零、负数、非整数，以及字符串格式错误、倒序或文件越界返回 `invalid_range`。
超出通用交换数据域的数值由作者标签或响应协议边界拒绝。

先检查参数类型、数组长度和元素类型；随后按 SPEC-BLT-002 登记合法路径依赖并读取材料；
最后解释范围字符串或检查数组数值和文件边界。坏范围值与缺文件同时出现时，先返回
`source_error` 并保留依赖；形状错误在读取前返回 `invalid_arguments`。
两种表示使用同一个行区间含义，等价有效范围的 Markdown、SourceSpan 和依赖完全相同。
行由 LF 分隔，CRLF 是一个行终止符；文件最后一个 LF 之后不额外计空行，空文件有零行。

区间包含 N 至 M 行的全部原始字节，包括选中末行已有的 LF 或 CRLF；
文件末行缺少换行时原样选择到 EOF。行号只定义选区，结果的来源仍同时声明精确 byte 区间。

<a id="spec-blt-006"></a>
## SPEC-BLT-006 include 代码标签与围栏

内置 include 生成源码代码块时，语言标签取 SPEC-BLT-003 材料类型对应的固定标签。

代码呈现的成功 Markdown 为一个反引号 fence：开栏、语言标签、LF、原始 payload、闭栏和一个 LF。
fence 长度比 payload 任意位置最长连续反引号多一，至少三个；两端 fence 相同。
payload 不以 LF 结束时，在闭栏前补一个 framing LF；该 LF 不属于来源区间。
payload 的缩进、行尾空白、CRLF 与反引号均保留。

<a id="spec-blt-007"></a>
## SPEC-BLT-007 结构路径

`id` 为非空字符串简写或非空 JSON 数组，统一解析为 `Name [Index] (Name [Index])*`。
字符串按通用字符串规则解码后以字面 `.` 分段；非空纯 ASCII 十进制数字段是下标，
接受前导零并按十进制数值归一化。其他非空段是精确名称，不 trim、不改变大小写、不生成 slug。
数组字符串始终为完整名称：不按点拆分，不把数字字符串当下标，允许真实空名称。
数组数值必须按交换数据域为 `0..9007199254740991` 内整数，`0`、`0.0`、`0e0` 等价。
负数、小数、布尔值、null、对象、嵌套数组不是路径元素。空路径、空简写段、首项下标、连续下标报 `invalid_arguments`。

从虚拟文件根开始，每层只取名称精确相等的直接子节点，并按原始声明起始字节升序排序。
同一实际声明不重复计数，类型、签名或可抽取性不影响同名编号。
没有候选报 `selection_not_found`；显式零基下标越界报 `selection_out_of_bounds`；
省略下标且不唯一报 `selection_ambiguous`，提供候选种类与起始位置。唯一候选也允许显式 `0`。
先消歧父节点，再进入子层；不能用后续名称猜父节点，不能全文件搜索或改用其他选择器。

节点自身可抽取与子节点候选是否完整是独立能力。已知名称和位置但不能抽取的候选仍占原下标，
选中时报 `unsupported_selection`，不改选下一项。当前层候选完整性不足也报此错误，
不能伪称唯一或给出可信下标。具体语言边界由实体规范定义。

名称含点、纯数字或空名称需数组，例如 `["重试.策略","0"]`、`["","安装"]`。
重复父标题下的子标题可写 `"重试策略.0.next_delay"` 或 `["重试策略",0,"next_delay"]`。
路径标识当前文件结构，数字下标是当前源码顺序，不是跨版本身份；插入不同名兄弟不改变选择，
插入或重排同名兄弟可以使显式下标指向另一项。唯一名称新增重名后，无下标引用报歧义。

<a id="spec-blt-008"></a>
## SPEC-BLT-008 link 页面目标与地址

`link` 恰好接受一个非空字符串位置参数，表示本轮所选输入文件的 root-relative 路径。
路径组成部分与符号链接边界沿用 SPEC-BLT-002；文件名中的 `#`、`?`、`%` 均为字面字符。
不接受命名参数。
位置参数数量、类型及未知命名参数不合法时报 `invalid_arguments`。

每轮由本次规范输入路径及 [SPEC-CLI-007](cli.md#spec-cli-007) 的映射建立只读页面目录。
选中的 Markdown 和六种源码语言具有相同目标资格，空 Markdown 页面也可作为目标。
仅被 include 引用的材料不自动成为页面。解析后目标不在本轮目录中，报 `page_not_selected`，
诊断保留查询路径；旧输出中存在对应页面不能满足要求，也不扩大输入选择。
目标查询越出 root 或无法安全确定边界时报 `source_error`。

合法参数形成可安全解析的 root 内查询后登记 file 依赖，保留查询拼写；未选中的缺失目标也保留依赖。
非法参数不产生依赖。已选目标原文由本轮 SourceStore 拥有，操作不重新读取另一版本。
结果恰好为编码后的相对 URL 字符串，不附加换行、显示文字、Markdown 链接包装或 HTML。
目标相对于当前内容实际输出文件的父目录计算，复用 [SPEC-REN-009](rendering.md#spec-ren-009) 的
相对路径与 UTF-8 百分号编码；同页链接仍使用相对文件名。
例如 `O/pages/docs/index.md.md` 指向 `docs/details.md` 时，目标为 `details.md.md`。

主请求的 link 由参数生成，来源指向真实父 Request.source；不把目标文件全文充当内容来源。
附录和报告的来源责任沿用 [SPEC-PLG-011](plugins.md#spec-plg-011)。
link 与 include 各自拥有参数语义；返回文字都是终值，不产生递归展开或额外插件批次。

<a id="spec-blt-009"></a>
## SPEC-BLT-009 跨语言指令设计

发行版设计的每个标准指令都必须跨语言：名称、参数和语义不得专属于 Markdown 或某一种编程语言。
相同指令在独立叙述输入与各语言提取后的正文中使用同一调用语法、标准能力和结果契约。
文件种类所需的注释识别、结构解析和原文呈现由对应适配器提供，指令通过共同的文件、结构和来源模型使用这些事实。
不能通过新增语言专属参数或仅对某种语言可用的指令绕过这一边界。

作者或项目插件负责输出格式的外围语法。例如 `link` 只产生 URL，作者可以写
`[下一篇]({% link "docs/details.md" %}#anchor)`，其中显示文字、括号和片段均为原始正文；
它们不成为 link 的参数，也不由 link 解析、生成或校验。

## 验收场景

| 条款 | 输入与动作 | 必须观察到 |
| --- | --- | --- |
| SPEC-BLT-001 | 同批多个请求、错误请求、空批次 | 每个 ID 一个结果；复用当轮文件事实；完整空响应 |
| SPEC-BLT-002 | 根外、非法 UTF-8、缺文件、空选区 | 请求失败，合法材料路径仍在依赖中 |
| SPEC-BLT-003 | Markdown、README、notes.txt 与各语言源码 | 使用相同结构路径选择标题或实体，按材料类型生成完整 Markdown |
| SPEC-BLT-003 | 选择器冲突、类型错误、未知命名参数 | 读取前报参数错误；合法选择保持原文字节和来源 |
| SPEC-BLT-004 | 同名嵌套、重复父标题、空标题、跳级、setext、伪标题 | 真实直接父子关系；锚点不作为标题名 |
| SPEC-BLT-005 | 字符串与数组的 CRLF、无末尾换行、单行、倒序和越界 | 等价范围有相同原文字节、来源与依赖；错误分类明确 |
| SPEC-BLT-005 | 坏范围或数组形状错误同时伴随缺文件 | 坏范围先报读取错误且保留依赖，形状错误在读取前失败 |
| SPEC-BLT-006 | 源码含四个反引号 | 使用该语言标签及五反引号围栏；原始字节保留 |
| SPEC-BLT-007 | 点号/数字/空名称、等价数值、非法路径、重排同名节点 | 名称保持；错误准确；下标遵循当前顺序 |
| SPEC-BLT-008 | 两篇选中的 Markdown 相互 link | 返回相对于各自实际页面的纯 URL，来源指向真实父请求 |
| SPEC-BLT-009 | 独立叙述输入及六种源码语言使用同一指令 | 参数和结果语义相同，语言适配器只处理各自原文边界 |
